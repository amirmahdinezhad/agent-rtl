## مقایسه و اصلاح

بستهٔ رسمی نسخهٔ قبلی از URL فید دریافت و پیش از استخراج با کلید Ed25519 رسمی اعتبارسنجی شد. تمام فایل‌های JavaScript زیر `.vite/`، از جمله entry اصلی `.vite/build/early-bootstrap.js` و سه preload، با نسخهٔ مبنا بایت‌به‌بایت برابرند. CSP هر دو HTML نیز برابر است؛ ارجاع assetهای renderer تغییر کرده است. API مورد استفادهٔ bridge، از جمله `registerPreloadScript` همچنان در کد vendor وجود دارد و تست Electron همان قرارداد main/preload و IPC را می‌آزماید.

مرزهای پیام کاربر، markdown پاسخ و شناسهٔ پاسخ، composer، سؤال، MCP form و صف از سورس renderer جدید بازبینی شدند. fixture محتوا به assetهای build 22530 و کلاس‌های فعلی پیش‌نمایش صف تطبیق داده شد؛ fixture جهت پاسخ نیز به نسخهٔ بررسی‌شده ارجاع می‌دهد. این‌ها DOM مصنوعی مطابق سورس هستند؛ DOM زندهٔ اپ و تعامل واقعی کاربر هنوز پذیرش نشده‌اند.

فهرست `supportedAppVersions` اکنون فقط `26.1023.51421` است. payload مشترک، منطق اصلی، حفاظت دریافت، امضا و rollback تغییری نکردند؛ بنابراین بازتولید userscript و تست اضافهٔ T3 بابت تغییر payload موضوعیت ندارد. تست‌های واحد موجود T3 در `npm test` اجرا شدند؛ GUI واقعی T3 در این نوبت اجرا نشد.

روی کپی staging از اپ واقعی، wrapper و payload آماده و امضای محلی بررسی شد. هش data area اصلی و حفظ‌شده یکسان بود:
`db6cfd35a85a1db569b5b1c60568255536c99f6c2ca4dd80e7895c5fb5122d55`.
متادیتای ASAR و digest بومی با هم تطبیق داده شدند؛ integrity فعال ماند. staging پس از بررسی حذف شد؛ commit نصب یا Launch روی اپ اصلی انجام نشد. روش موجود امضای محلی، entitlementهای وابسته به Team اپل را حذف می‌کند؛ ورود، Keychain و دسترسی‌ها باید در پذیرش دستی بررسی شوند.
