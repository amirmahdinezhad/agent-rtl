# T3 Code update workflow

Start when the user reports a new T3 version or requests a T3 compatibility check. For requests without an app name, follow [app selection](app-update-workflow.md).

1. Read `AGENTS.md`, [release instructions](updates.md), previous report and configuration. Preserve existing changes and work on a `codex/` branch. Record actual bundle/ASAR path, identity, version/build, Agent RTL, macOS and architecture; CLI or Codex versions are not the target.
2. Match the official T3 version and download against the machine. Distinguish patch removal, structural changes, compatibility restrictions and download failures. The Codex feed is not a T3 feed. Do not claim compatibility for unchecked versions; record access limitations.
3. Compare main/preload, Electron APIs, scheme and nested chat routes, HTML/CSP, assets, DOM/composer and response IDs, CSS, native modules, integrity, signing and Team ID features. Preserve original logic and rollback. Retain T3's vendor-disabled integrity state without weakening Codex's active-integrity requirement.
4. Fix shared code and limited resolver/context/target differences; check Codex regressions. Keep T3 storage, fonts, runtime, backups, jobs, feeds and removal independent. `supportedT3Versions` must accept only checked versions. Regenerate the userscript after shared payload changes.
5. Run `npm test`, `test:language` and shared `test:gui`, then GUI/font checks with `ARTL_TEST_TARGET=t3` and `test/t3-design-smoke.mjs` against that T3's actual CSS/DOM. Fixtures do not establish real-app acceptance. Record skipped checks and reasons.
6. Build a separate Setup/ZIP with `ARTL_TARGET=t3 ARTL_LOCAL_CANDIDATE=1` and an explicit output. Run `test:installer` and `test:events` with `ARTL_TARGET=t3` against that same Setup. Package/manifest target must be t3 and the local feed disabled. Record version, base commit, full diff, source/ZIP hashes, signing, preservation of original logic and packaged-runtime agreement.
7. Deliver `docs/compatibility/t3-<version>.md` and the exact Setup. Do not close or replace the original app yourself. The user performs Launch.
8. Apply the [shared manual checklist](codex-update-workflow.md#user-manual-test-checklist) using T3's name/path/build/candidate. Also check nested chat routes, response-direction isolation between environments, Touch ID/passkeys and preservation of Codex. Default state: `~/Library/Application Support/Agent RTL T3/`.
9. Record each result, status/renderer-ready evidence, signing/integrity and limitations. General acceptance does not confirm every detail. Remove RTL must restore the original same-version T3; never restore an old backup over a newer app update. A substantive change after acceptance requires a new candidate and checks.

Manual acceptance and explicit GitHub authorization are separate requirements. After both, follow the [release steps](updates.md) with a separate T3 package, feed and manifest. Prereleases use `--prerelease --latest=false`. Test actual GitHub download/updating separately. Acceptance of one app does not establish acceptance of the other.
